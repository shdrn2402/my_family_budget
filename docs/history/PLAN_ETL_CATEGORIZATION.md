## 1. Проблема
В данный момент, при загрузке банковской выписки (Excel) через Telegram:
1. Сырые описания транзакций (например `YELLOW MARKET 12345`) сохраняются в БД "как есть".
2. Категория (`category_id`) остается `NULL`, потому что бот даже не пытается сопоставить сырую строку с базой алиасов (`item_aliases`).
3. Логика очистки строк (удаление цифр, суффиксов בע"מ) живет изолированно в одноразовых скриптах `scripts/extract_aliases_isracard.py` и недоступна боту.
4. Логика динамического определения категорий по сумме (Yellow: Топливо vs Снеки) вообще не реализована.

## 2. Архитектурное Решение
Мы внедряем паттерн ETL (Extract, Transform, Load) на уровне Python-бота:
* **Extract:** Парсим Excel (уже работает в `importer.py`).
* **Transform (Новое):** Прогоняем описание через единый сервис `categorizer.py`, очищаем строку, применяем динамические правила (сумма) и ищем совпадения в загруженном словаре `item_aliases`.
* **Load:** Сохраняем в БД уже готовую транзакцию с правильным `category_id` (работает в `database.py`).

## 3. Шаги реализации (Implementation Plan)

### Шаг 1: Создание `bot/services/categorizer.py`
Создать новый модуль, который будет отвечать за всю логику распознавания мерчантов.
* **Функция `clean_business_name(raw_name)`**: Перенести логику из `scripts/extract_aliases_isracard.py`.
* **Функция `auto_categorize(raw_name, amount, db_aliases)`**: 
  1. Вызывает `clean_business_name`.
  2. **Динамические правила**:
     * Если имя содержит `YELLOW` или `אלונית` или `פז`: 
       * Если сумма расхода `> 100` ₪ -> Категория `26` (Топливо).
       * Иначе -> Категория `17` (Снеки/Кофе).
     * Если имя содержит `דן דיל` (Dan Deal):
       * Если сумма расхода `> 50` ₪ -> Категория `24` (Хозтовары).
       * Иначе -> Категория `17` (Сладости).
  3. **Стандартный поиск**: Если динамических правил нет, ищем очищенное имя в `db_aliases`.
  4. Возвращаем найденный `category_id`.

### Шаг 2: Обновление загрузки в `bot/handlers/document.py`
* Перед вызовом `save_transactions_bulk`, загрузить все алиасы из БД в словарь (`db_aliases = await get_all_item_aliases()`).
* Пробежаться по списку `transactions`, вызвав `auto_categorize(...)` для каждой строки, и обогатить её правильным `category_id`.

### Шаг 3: Обновление `bot/services/importer.py`
* Убедиться, что парсеры (Leumi, Isracard) правильно формируют словарь транзакции и не теряют оригинальное сырое описание (`description`).

### Шаг 4: Обновление offline-скриптов
* В файлах `scripts/extract_aliases_isracard.py` и `scripts/extract_aliases_fibisave.py` удалить дублирующуюся логику очистки.
* Импортировать и использовать `clean_business_name` из `bot.services.categorizer`, чтобы правила всегда были синхронизированы между ботом и утилитами.
